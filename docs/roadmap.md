# 路线图

## 产品是什么

一个 macOS 菜单栏工具：**拖一张图进来 → 理解它的风格 → 调参偏移 → 产出可直接用的生图提示词**（有 API 就直接出图）。

关键判断：不做垫图式的"抄"。垫图把像素直接喂给模型，得到的是复制品，而且**没有旋钮**——你没法对一张垫图说"色相转 20 度、密度降一档"。本工具先把风格解析成结构化的 `StyleSpec`，再在字段上做受控变换，所以每一次偏移都能说清改了什么。

> 随机重跑得到的是噪声，受控偏移得到的是变体。

垫图不废弃，但降级为保底修复路线：文生图两轮都不像时才上。

---

## 两条轨道

两条轨道用**不同环境**，刻意分开，互不抢资源。

| | Track A：Mac App | Track B：调参盘验证 |
|---|---|---|
| 环境 | Swift / SwiftPM，调 Anthropic API | Claude Code + `core-ts/` 命令行工装 |
| 产出 | 每天用的工具 | 可靠的偏移规则 |
| 成本 | API key 按量计费 | 走订阅，零额外费用 |

**依赖方向是单向的**：Track B 的结论喂给 Track A，A 不阻塞 B。

**规则永远先在 `core-ts/` 改、跑通真图验证，再移植进 Swift。** App 不 ship 未经验证的规则。

### A1 的范围

```
菜单栏图标（常驻投放目标）
   ↓ 拖入一张或多张图
待办队列（缩略图 / 状态 / 暂停 / 重试）
   ↓ 后台逐张调 Claude 出 StyleSpec
结果页：风格 DNA + 即梦版 + GPT Image 2 版，一键复制
```

不做调参盘，不做生图。这条链路通了就能天天用。

**设置项从 A1 就要有三个字段**：`base_url` + `key` + `model`。只留 key 输入框，走中转的用户（包括你自己）用不了；而这和以后"用户填自己的 API"本来就是同一个设计。

### A3 待单独讨论

生成环节的交互设计（怎么选模型、参数怎么暴露、结果怎么回流做对比）没有讨论过，A3 开始前单开一轮。

## Track B：调参盘

| 阶段 | 内容 | 规模与做法 |
|---|---|---|
| **B0** | 补 drift 引擎：风格轴 / 色彩轴 / 强度环 + 字段 diff 输出 | 纯代码，无外部依赖 |
| **B1** | 30 张真图逐张验证偏移是否有意义 | Claude Code 内手跑 |
| **B2** | 100 张 | 必须上 `claude -p` 无头批处理 |
| **B3** | 1000 张 | 成本和时间单独算一次再决定 |

### 十字轴设计（待 B1 验证）

**风格盘** — X 轴形态（有机流动 ↔ 几何硬朗），Y 轴密度（疏 ↔ 密）
映射 `form_language.geometry/edge` 与 `composition.density/subject_coverage/negative_space`。

**色彩盘** — X 轴色温（冷 ↔ 暖），Y 轴调性（暗调 ↔ 亮调），外加独立的饱和度滑杆
映射 `palette`（hex + ratio 上做真正的色彩运算）与 `color.*`。

**强度环 0–3** — 中心点永远是原图的忠实值，环决定每次拖动走多远。"回到原点"永远可用。

有一个不对称必须在界面上老实呈现：**色彩盘能实时预览色块**（纯计算、零延迟），**风格盘不能**——它只能显示字段 diff，要看效果必须真的出图。

### B1 的真实瓶颈是出图，不是代码

判断"这次偏移有没有意义"必须看到生成结果。30 张 × 3~4 档 = 90~120 次生成，手动贴到网页跑不动。

建议 B1 先按 **30 张 × 2 档 = 60 次**手动跑，验证方向对不对；到 B2 再决定要不要为自动化花 API 的钱。

## 仓库分工

| 目录 | 归属 | 说明 |
|---|---|---|
| `schema/` | 共用 | StyleSpec / Brief 的单一事实来源，两边都读它 |
| `knowledge/` | 共用 | 方法论原文，分析指令和编译适配器的源头 |
| `core-ts/` | Track B | TypeScript 参考实现 + 验证工装 |
| `app/` | Track A | Swift App |
| `SKILL.md` | 过渡 | A1 跑通后删除 |

### 为什么容忍两份实现

同一套规则有 TS 和 Swift 两份实现，确实有漂移风险。用 **43 个测试用例**当共同契约来盯住：期望字符串逐字相同，两边都得过。

换来的是 Track B 能在 Claude Code 里零成本快速迭代，而 App 只接收已验证的规则。

## 分支策略

```
main   ← 保持 v1.0.0 原样，两个 skill 软链继续工作
  └── app (worktree: ../image2prompt-app)   ← A0/A1 全部在这里
```

用 **git worktree** 而不是 `git checkout`：`~/.claude/skills/image2prompt` 和
`~/.codex/skills/image2prompt` 两个软链都指向仓库工作目录，切分支会当场换掉它们看到的文件。
worktree 给 app 分支单独一个目录，原目录永远停在 `main`。

A1 跑通、App 真的能用之后，才合并回 `main` 并删除 `SKILL.md`。
