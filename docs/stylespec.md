# StyleSpec v0.1 字段说明

机器可读的定义在 [`schema/stylespec.v0.1.json`](../schema/stylespec.v0.1.json)。这份文档解释**为什么这么设计**。

## 它是什么

一张图被"看懂"之后的结构化结果。三个用途：

1. **编译提示词的输入**——各模型适配器都读它，而不是读原图。
2. **调参盘的操作对象**——偏移做在字段上，不是在提示词文字上改。
3. **图库的原子单位**——每张图分析一次、存一份 JSON，检索和复用都建立在它上面。

## 最重要的设计：内容层和风格层物理隔离

```
content.*      ← 这张图画了什么     （换主体时整个丢弃）
其余所有字段    ← 这张图长什么样     （换主体时完整保留）
```

`content` 存"一个女孩站在海边"；`style_dna` 存"低饱和冷蓝，大面积天空负空间，主体位于下三分之一，柔和逆光，胶片颗粒"。

**检验标准**：把任何新主体塞进风格块都成立。如果风格描述里出现了原图的具体物件、品牌或文字，那就是**内容泄漏**——`content_leakage` 字段记录它，lint 规则会报错。

这条隔离是整个产品成立的前提。风格能被复用，是因为它跟内容无关。

## 字段分组

| 组 | 字段 | 作用 |
|---|---|---|
| 元信息 | `schema_version` `source` `confidence` `notes` | 版本、来源、置信度、不确定项 |
| 分类 | `ad_type` `medium` `medium_detail` `style_family` | 广告图类型、媒介、风格流派 |
| **内容** | `content` | 主体、场景、品牌标记、画面文字、关键词 |
| 构图 | `composition` | 景别、角度、画幅、主体位置与占比、负空间、网格、密度、出血、层次、对称、视觉动线 |
| 色彩 | `palette` `color` | 色板（hex + 占比）、饱和度、色温、对比、和谐关系、明暗调性 |
| 光线 | `lighting` | 方向、软硬、对比、光源、时段 |
| 材质 | `material` | 表面质感、纹理叠加 |
| **形态** | `form_language` | 几何/有机、边缘、圆角、笔画粗细、重复、间隙规则 |
| 排印 | `typography` | 有无文字、字体类别、字重对比、字号层级、对齐、大小写、文案安全区 |
| 气质 | `mood` `use_cases` | 氛围词、适用场景 |
| 交付 | `style_dna` `style_dna_en` | 可直接套用的风格描述块 |
| 检查 | `content_leakage` | 检出的内容泄漏项 |

## 为什么 `form_language` 单独成组

实测教训：**形态词写错一个，生成方向全偏。**

"液态/流动"会把模型推向有机泡泡字；想要几何感必须明确写"平直边缘 + 大圆角"。几何圆角和有机液态是两种完全不同的气质，混着写模型就乱猜。

所以 `geometry`、`edge`、`corner_radius_note` 是分开的三个字段，逼分析阶段把话说清楚，而不是塞进一句形容词里。

调参盘的风格轴 X 就是在这组字段上移动。

## 为什么 `palette` 是 hex + 占比

因为**色彩偏移是真正的运算**，不是换形容词。

有了 hex 和 ratio，"保持色相关系整体降饱和"、"保明度结构旋转色相 20 度"、"只换 accent 保 base"、"明暗反转"全都是确定性计算，能**实时预览色块**，零 API 调用。

这是垫图给不了的能力，也是色彩盘比风格盘体验好的原因——形态的效果必须真的出图才看得到，颜色不用。

## `confidence` 不是装饰

`confidence.overall` 和 `uncertain_fields` 要如实填。看不准的维度标出来，比编一个确定的答案有用——下游可以选择追问、重看、或者在提示词里回避这个维度。

## 版本演进

`schema_version` 是必填字段。改 schema 就要升版本号，并且：

- `core-ts/` 和 `app/` 两侧同步
- `app/Sources/Image2PromptCore/BuildInfo.swift` 里的 `styleSpecVersion` 跟着改
- 已存的 StyleSpec JSON 要能被识别成旧版本，不能静默误读
