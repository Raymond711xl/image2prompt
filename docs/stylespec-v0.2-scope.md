**状态：已实施。** 下面六条已经写进代码：`schema/stylespec.v0.2.json`、core-ts 全链路

**实施时发现的一条架构陷阱，记下来避免下次再踩：** `content.*` 是隔离区，
`compile/adapters` 里的 text2img 从不读它（编译时用的是 Brief 的新内容，不是原图内容），
这是"换主体时丢弃"设计的自然结果。但 `composition.panel_count/panels/element_stacking`
在 `composition` 块里，是**会被编译**的——第一版 `element_stacking` 顺手写成
"中央像素马图形"这种点名原图物件的写法，被 `transfer-test` 抓了现行（跨主体测试直接检测到
内容泄漏）。已修：`lint/rules.ts` 的 L1 检查表加了 `element_stacking` / `panels[].role`，
两侧分析指令也加了这条"必须写成抽象角色"的规则。**以后往 `composition` 塞新字段，先确认
它是不是真的换主体也成立，不成立就该放进 `content`，或者干脆不编译。**

## 版本号：0.1 → 0.2

不是 1.0——产品还没到"可以打包发布"的完整度，后面喂更多图大概率还要再改字段。

## 这轮定案的原则

- 只做 28 张证据里**高频 + 高杀伤力**的几类问题，其余明确挂账，等喂更多图再看要不要加。
- 前台卡片保持人看得懂的颗粒度；后台（喂给生成模型的结构化数据）可以比前台展示的更细，
  但后台多出来的判断都要能"翻译"成前台一句人话，不能前后台各说各话。
- 风格 DNA 中英文不再同权重：中文是给人看的展示层，英文单独存一份供生成模型使用，
  不再当成两份要对齐维护的"正文"。

## 本轮定案：6 个改造点

### 1. 精确画幅（零成本，直接从文件读）

- 新字段：`source.width` / `source.height` / `source.aspect_exact`
- 解决：精确画幅（4/28），也是 #04、#12、#22 画幅误差的根因之一
- 前台：详情页比例数字从"3:4"这种粗类别，换成精确值（如 0.75）；不新增卡片
- 后台：`aspect_ratio` 类别字段保留做检索/展示，新增的精确数值用来锁编译时的画布
- 备注：本条不需要模型猜，是这轮唯一"纯白嫖"的一条

### 2. 文字版式全面升级（本轮最大头，范围比最初写的更宽）

不是只解决"怎么断行"。核对范围时用户明确指出：文字排版不只是断句，还包括**颜色、大小、
有没有被变形处理、以及多段文字之间靠什么隐形关系互相咬合**——这些都是肉眼查排版时最先看出来的
维度，必须一起进这轮，不能只做换行。

`content.on_image_text` 每一段文字新增字段：

| 字段 | 记什么 | 对应哪类反馈 |
|---|---|---|
| `layer` | 前/中/后三档，不做精确坐标 | 重叠遮挡（10/28） |
| `ocr_status` | exact / approx / unclear 三档 | OCR 污染（2/28，#17） |
| `line_breaks` | 实际怎么分行，按顺序列出每一行，不是整句存成一个字符串 | 文字几何与换行（19/28） |
| `color` | 这段字的颜色（优先 hex，取不准写简短描述） | 空间色彩（14/28）在文字上的部分 |
| `relative_size` | 相对画面里其他文字的大小级别（最大/大/中/小/最小），不是像素字号 | 文字层级关系 |
| `distortion` | 有没有被变形：沿路径弯曲、透视斜切、旋转、拉伸、描边分层立体字，平直无变形写 none | #08、#28 这类艺术字案例 |
| `typeface_note` | 只有这段字体明显不同于整体判断时才填（比如正文无衬线、但这个标题是手写花体） | #16、#17 的定制字形问题 |

`typography` 另外新增一个整体字段 `implicit_alignment`：多段文字靠什么隐形关系互相咬合
（比如共用同一条左对齐线、顶边对齐、行距和字块间距保持统一比例）——这是"文字构成的隐形边际和
空间"这件事在 schema 里的落点，写成可迁移的抽象规则，不点名具体文案内容。

三张图直接栽在换行/层级上：#01（边界留白/换行未编码）、#02（文字块被合并成少数超大块）、
#06（LIFE/FAKE/DETAILS 本该一词一行，被合成一行）。成本都不高，分析时顺手记一下即可，
不需要精确坐标或像素测量。

- 解决：文字几何与换行（19/28，全表最高频）、OCR 污染（2/28）、部分空间色彩（14/28）
- 对应旧条目：`analysis-gaps.md` 的 G5——当时就写着"做塞入自己内容之前必须先做"，
  这轮证据（19/28）够格让它从挂账毕业
- 前台：详情页"排印"卡片加一行"共 N 段文字"，可展开看每段的区域/层级/颜色/大小/变形/
  换行方式/是否原文照抄
- 后台：编译器看到 `ocr_status=unclear` 就不再当 literal text 编译，直接堵死 #17 那类 bug；
  `line_breaks` 逐行进提示词；`color`/`relative_size`/`distortion` 按段落写进文字描述，
  不再让模型自己决定这段字长什么样

### 3. 载体与画面事实

- 新字段：`content.carrier_type`（枚举：平面设计原图 / 印在物体上的照片 / 截图 / 实景照片，
  带 confidence）；不确定时用 `content.carrier_candidates` 存多个候选，不擅自定死一种
- 解决：载体、边框与画芯（7/28），是 #04（书籍变商品样机）、#07（作品页拍扁成一张图）、
  #23（T 恤被过度确定）三张 D/C 级图共同的病根
- 前台：内容卡片加一行"载体判断：xxx（置信度高/中/低）"
- 后台：置信度低时，编译进去的描述保留候选而不是强行锁死成一种

### 4. 面板结构（只有多面板图会触发，单面板图完全不受影响）

- 新字段：`composition.panel_count`（默认 1）；只有 >1 时才出现 `panels[]`，
  每块记大致区域和角色
- 解决：面板/拼贴结构（4/28），是 #07（三面板被拍扁）、#28（六格拼贴被清理成规则网格）
  从不及格翻身的关键
- 前台：只有 `panel_count>1` 时，详情页多一句"检测到 N 个版块"
- 后台：多面板时编译器分别处理各面板的排版/风格，不再拍扁成一个场景

### 5. 禁止脑补规则

- 新字段：`content.visible_only`（默认 true）、`content.external_expansion_risk`
  （标出画面里出现的品牌/IP 名，提示这类词容易触发模型自己的常识联想）
- 解决：外部语义/IP 先验（3/28），专治 #04（《大友克洋全集》被生成一本新漫画书）、
  #23（优衣库 BLEACH 联名被换成常见主角群像）
- 前台：不需要新卡片，是分析指令层面的硬规则，用户看不到多的 UI，但结果会变
- 后台：分析指令加一条硬性禁令 + 编译器加一句 negative constraint

### 6. 前后遮挡关系（基础版，不做精确坐标）

- 新字段：主要对象按前后顺序给一个简单序号，只回答"谁在前谁在后"，不做 bbox/mask
- 解决：重叠、遮挡与层级（10/28），是多张 B/C 级图的共同问题
  （#03、#05、#06、#09、#16、#22、#25、#28）
- 前台："视觉语法"卡片加一行人话列表："元素前后关系：A 在前，B 在后…"
- 后台：编译器按顺序生成前后关系提示
