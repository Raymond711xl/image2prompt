# 得意忘形 · Formless

**中文** · [English](README.en.md)

macOS 菜单栏工具：**拖一张图进来 → 理解它的风格 → 调参偏移 → 产出可直接用的生图提示词**。

## 名字

「得意忘形」是个双关，三层意思都是认真的。

**第一层，它在提醒你别得意忘形。** 工具能让你快十倍，但快不等于好。审美是实打实积累出来的，
看过多少张好图、拆过多少个版式、失败过多少次，这些没有捷径。一个把提示词递到你手上的工具，
不该让你产生"我已经会了"的错觉。

**第二层，它只是工具，形还得你自己填。** 这里不生产作品，只把参考图拆成可读可改的结构。
拖进来的图是你选的，往哪偏是你定的，最后长成什么样取决于你给了什么主题、什么文案、什么判断。
工具负责把"我说不清但我想要这种感觉"变成能操作的字段——剩下的是你的活。

**第三层，它字面上就在忘形。** 程序真正做的事是把参考图的**形**（画了什么：主体、文案、品牌）
忘掉，只留下**意**（怎么画的：字体、色板、构成、质感）。这是硬规则不是修辞——`style_dna`
里出现任何 `content` 里的词，lint 直接报 error。忘不掉形的结果叫抄图，忘掉了才叫风格。

> 得其意，忘其形。

英文名 `Formless` 承接第三层，同时是可执行文件名和 bundle id 里的那个词。

## 它和「垫图」的区别

垫图把像素直接喂给生图模型，得到的是复制品，而且**没有旋钮**——你没法对一张垫图说
"色相转 20 度、密度降一档"。

本工具先把风格解析成结构化的 `StyleSpec`，再在字段上做受控变换，所以每次偏移都能说清改了哪几个字段。

> 随机重跑得到的是噪声，受控偏移得到的是变体。

垫图没有被废弃，但降级为保底修复路线：文生图两轮都不像时才上。

## 整体想法

一句话：**把"看图"和"编译"分开，各交给擅长的一方。**

```
你拖进一张图
   ↓  看图 —— 交给 agent（Claude Code / Codex / API）
StyleSpec JSON —— 结构化的风格描述，可存、可检索、可复用、可改
   ↓  编译 —— 交给确定性代码（不是模型现场发挥）
即梦版提示词 + GPT Image 2 版提示词
```

三个判断撑着这套结构：

**看图必须用模型，编译不该用模型。** 判断"这是什么风格"只有视觉模型做得到；但把风格描述
翻译成某个生图模型吃得下的提示词，是一堆有明确对错的规则——即梦不能用否定式、画质词超过两个
反而变糊、垫图编辑指令缺了保护清单就会把无关元素一起改掉。规则写成代码就能被断言、被测试、
被复用；交给模型每次现场发挥，就只能碰运气。

**`StyleSpec` 是原子单位，不是中间产物。** 每张图分析一次、存一份 JSON。以后的图库、检索、
"把这张的色板配那张的构成"，全都建立在它上面。这也是为什么它有 schema、有 lint、有测试。

**识图成本要压到零。** 全库几千张，识图是最贵的一环，生图只是零头。所以默认走本地
agent——调你机器上已经装好的 `claude` / `codex` CLI，用你已经付过的订阅额度，不必再买 API。

## 开发阶段

两条轨道，刻意用不同环境，互不抢资源。依赖方向单向：Track B 出结论喂给 Track A。

| | Track A：Mac App | Track B：调参盘验证 |
|---|---|---|
| 环境 | Swift / SwiftPM | Claude Code + `core-ts/` 命令行工装 |
| 产出 | 每天用的工具 | 可靠的偏移规则 |
| 成本 | 走本地 agent 则为零 | 走订阅，零额外费用 |

**规则永远先在 `core-ts/` 改、跑通真图验证，再移植进 Swift。** App 不 ship 未经验证的规则。

| 阶段 | 内容 | 状态 |
|---|---|---|
| **A0** | 仓库从 skill 改造成 App 项目；SwiftPM 骨架 | ✅ 完成 |
| **A1** | 拖入 → 待办队列 → 后台反推 → 出双版本提示词 | 主链路已跑通，验收未过 |
| **A2** | 调参盘（十字轴：形态/密度、色温/调性 + 强度环） | 等 B1 结论 |
| **A3** | 生图出口 | 待设计 |
| **B0** | drift 引擎：轴移动 + 色彩运算 + 字段 diff | ✅ 完成（547 行，25 个测试） |
| **B1–B3** | 30 张 → 100 张 → 1000 张真图，逐级验证偏移是否有意义 | 待开始 |

A1 实测：单张完整分析约 **2 分 30 秒**（本地 agent），schema 校验首次通过，
lint 抓出 2 条内容泄漏并已修分析指令。剩下的是 10 张连跑的验收、以及 Anthropic API 接入。

`StyleSpec` 目前是 **0.2** 版：28 张真图跑完 Image2 复现回归测试后，基于证据把精确画幅、
文字版式（换行/层级/颜色/大小/变形/OCR 状态）、载体判断、面板结构、禁止脑补、前后遮挡关系
六组字段补进了 schema，两侧代码和测试均已同步。定案范围和取舍见
[`docs/stylespec-v0.2-scope.md`](docs/stylespec-v0.2-scope.md)。

完整路线、十字轴设计、成本估算见 [`docs/roadmap.md`](docs/roadmap.md)；

## 安装与使用

需要 Swift 6.1+（Command Line Tools 即可，**不需要 Xcode**）。

```bash
cd app && ./Scripts/bundle.sh release install
```

装进 `/Applications/得意忘形.app`，双击启动，菜单栏出现 ✨ 图标。图标本身是投放目标：
把图直接拖到菜单栏图标上即可入队。

### 接自己的 agent（推荐，不花 API 钱）

设置 → 识图引擎，选：

| 选项 | 说明 |
|---|---|
| Mock | 假数据，不联网。开发和体验路径用。 |
| Claude Code | 调本地 `claude` CLI，用你的订阅额度 |
| Codex | 调本地 `codex` CLI |
| 自定义 agent | 填可执行文件 + 参数模板 + stdin 开关，任何"读指令吐文字"的 CLI 都能接 |
| Anthropic API | 填 key（待接入） |

点「检测」确认 CLI 找得到。

**两个限制**：agent 只能看图不能生图，生图仍需复制提示词到网页或接生图 API；
另外这个模式要启动子进程，与 Mac App Store 沙盒不兼容（直接分发不受影响）。

## 目录结构

```
├── schema/          StyleSpec / Brief 的单一事实来源，core-ts 和 app 共用
├── knowledge/       方法论原文：设计风格库、模型规范、修图模板
├── core-ts/         TypeScript 参考实现 + 验证工装（Track B）
├── app/             Swift App（Track A）
├── docs/            路线图、StyleSpec 说明、改造方案
├── pictext/         参考图语料，本地保留、不入库
└── SKILL.md         过渡期保留，A1 验收后删除
```

`schema/` 和 `knowledge/` 刻意放在仓库根：两条轨道都要读它们，复制两份必然漂移。

## 由来

本仓库前身是 `image2prompt` skill——一个在 Claude Code 和 Codex 里跑的参考图反推提示词工具。

三轮真实测试沉淀下来的东西（形态词避坑、先问再开方、编辑边界四纪律）没有丢：它们变成了
`schema/` 里的字段设计、`core-ts/src/lint/` 里的检查规则、和 `knowledge/` 里的知识库。
下线的只有 `SKILL.md` 这个调度器——它判断模式、编排流程的职责，由 App 的界面接走。
